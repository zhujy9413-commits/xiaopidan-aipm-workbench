# 竞品分析表制作

## 目标与范围

交付能帮助用户回答本次问题的竞品分析表。分析目的决定竞品和维度，避免把功能罗列当成分析。

只沉淀可复用的思考方法、流程、质量标准和证据边界。本次项目和竞品可出现在交付表中，不得自动写回 Skill 或沉淀为业务案例。不要扩展为独立报告、立项建议、需求池或 PRD。

## 1. 梳理需求并确认

读取用户已有资料，提取已知信息，避免重复询问。优先澄清会改变研究范围或比较口径的问题：

- 这张表要回答哪个具体问题，支持什么决策？区分新项目、产品迭代、竞品动作、定价等目的，但不要求每次分析全部目的。
- 项目阶段、目标用户、核心任务和使用场景是什么？有哪些已知需求证据和约束？
- 比较的市场、地区、平台、产品版本、免费或付费档位是什么？已有竞品和排除对象有哪些？
- 用户能提供哪些资料或体验记录？有哪些访问、时间或研究深度限制？

分轮提问，每轮聚焦少量关键问题。提供选项时标注推荐并允许自由回答。有可用选项弹窗且用户希望使用时，优先使用弹窗；发出后等待用户回复，避免紧接着发送会收起弹窗的结束消息。

汇总一份简短的分析任务说明，包括目的、背景、范围、候选竞品及选择原则、主要比较维度、证据缺口。明确尚待确认的内容，请用户确认后开始正式研究和制表。若对话中已经确认同一范围，直接沿用，不重复索要确认。研究中遇到会改变核心范围的新问题时再追问，普通资料缺口记录为未知或待验证。

## 2. 选择竞品

围绕同一用户任务检查四类对象：

| 类别 | 判断依据 |
| --- | --- |
| 直接竞品 | 争夺相同人群，解决相近任务，方案有直接竞争关系 |
| 间接竞品 | 满足同一需求，但通过不同产品或方式实现 |
| 替代品 | 用户当前实际采用的工具、人工流程或组合方案 |
| 潜在竞品 | 尚未进入该范围，但有进入能力和相关动向证据 |

按决策相关性、代表性和证据可得性选取，说明入选理由；不固定数量，不强制每类都有，不只选择知名产品。四类边界可能重叠，按本次场景解释分类。

未找到竞品时，检查搜索词、地区和任务定义，继续寻找替代流程及历史尝试。不能直接推断市场空白、伪需求或方向已失败。潜在竞争能力也不能等同于确定进入。

## 3. 设计统一比较维度

默认每列一个竞品、每行一个维度，右侧附“横向差异”“本项目启发”“待验证项”。用来源编号关联证据。列头或基础信息行注明竞品类别、版本、档位和研究日期。

以下是候选维度，按目的选取和细化，不要求全部填满：

| 层次 | 可比较内容 |
| --- | --- |
| 市场 | 市场范围和阶段、竞争格局、进入条件；规模数据的统计口径 |
| 定位 | 目标人群、核心价值、主要任务与场景 |
| 用户 | 关键旅程、输入与完整输出物、操作成本、人工介入、失败恢复、用户反馈 |
| 技术 | 可见工作流程、自动化边界、工具或 Agent 分工、集成能力 |
| 模型 | 有证据的模型及选择理由、任务效果、延迟、稳定性 |
| 基础 | 数据来源和流转、知识更新、权限与隐私、价格、计费、可证实的成本 |

0→1 通常更全面地观察价值与实现链路；迭代分析聚焦相关任务和功能。根据具体目的调整，不把阶段当成强制拆解模板。

每行应有明确比较问题和统一口径。避免把不同任务、平台或价格套餐混为一谈；确有差异时说明条件。不适用、未公开、无法访问、未实测分别标注，不能一律写“不支持”。

## 4. 研究与证据管理

主动寻找公开资料，并结合用户提供的材料。按实际问题选择渠道，无须机械覆盖所有渠道：

- 实际体验：主流程、输入、输出、限制和异常处理。
- 官方资料：产品说明、帮助文档、更新记录、定价页、财报。
- 用户反馈：应用商店、社区、测评；记录样本时间、版本和场景。
- 市场信息：融资、招聘、第三方数据、榜单、行业研究。

注册、付费、上传用户数据等操作遵守当前授权边界；无法体验时提供具体补证任务，不声称已经实测。

区分三种内容：

- **事实**：来源直接支持，注明条件；官方宣称的性能仍是官方宣称，不能写成实测结果。
- **推断**：说明依据和不确定性，不能包装为已知内部实现。
- **未知**：保留缺口，说明是否影响本次判断及如何验证。

关键事实、数据和判断附可追溯来源与日期。来源清单记录编号、链接或材料位置、标题、发布或更新时间（可得时）、访问日期、支持的内容；实测另记测试时间和条件。引用需能支持对应单元格，不堆无关链接。

价格须标明地区、币种、档位、周期、额度与超额规则。第三方规模、流量和收入估算标注统计口径和估算性质。评论用于识别问题线索，不能由少数差评直接推导普遍发生率。

竞品未披露模型、Agent 架构、数据流或成本时，不凭界面或输出断言内部实现。不把售价当成本，也不凭模型单价推导完整经营成本。来源冲突时检查日期、版本和口径，无法消解则保留冲突。

## 5. 必要时评测 AI 输出

当结论依赖准确性、质量、效率或稳定性时，设计同一任务和评价标准。能实测则执行；无条件则列为待验证，不用宣传材料替代实测。

使用有代表性的相同输入，记录产品版本、档位、模型选项、提示词、工具权限及其他影响结果的条件。按任务选择成功率、事实正确性、完整性、可用性、延迟、费用、人工修正量等指标，不机械套用全套指标。

保留输出及判断依据。单次体验只支持该次观察；涉及稳定性时需要重复测试或适当样本。不同环境导致不可比时披露限制，不强行排名。评测计划和结果压缩进表格或必要的证据附表，避免扩展为独立评测报告。

## 6. 写差异与项目启发

先呈现可比证据，再提炼差异及对本项目的含义。启发必须连接目标用户、需求或场景，不能泛写“体验好”“功能全”“加强差异化”。不要求每行都有启发，没有足够证据时说明无法判断。

可用“目标用户最重视什么、竞品在哪个条件下满足不足、原因是什么”组织差异化假设。区分“当前没做”“当前做得不足”“存在难以满足的约束”；只有充分证据才能断言“做不了”。差异不自动意味着用户需要、愿意切换或愿意付费。

主动检查反方：竞品的优势是否足以消除本项目机会？用户为什么继续使用替代方案？所谓空白是否已有隐性解决方式？把有证据的反例、限制和验证任务落入相关行，不为迎合用户而选择性呈现信息。

不默认使用加权总分。只有评分能回答本次问题，且评价尺度和权重有依据时才使用，并说明不确定性；不把未知值记为零分。

## 7. 交付与质量检查

默认先在对话中交付表格。说明本次目的、范围和日期，提供主表及必要的来源、评测证据附表；内容过宽时按层次拆成同口径子表。结论和启发保持在表格内，只附必要的简短说明。

交付前检查：

- 竞品和维度是否能回答确认过的问题？是否遗漏相关替代方案？
- 是否同口径横向比较，条件差异是否披露？
- 关键事实能否追溯，事实、推断、未知是否区分？
- AI 效果判断是否有相应测试证据，未实测是否明确？
- 差异和启发是否有依据，反方证据是否被保留？
- 待验证项是否具体，是否标明对判断的影响？
- 是否仅交付竞品分析表及必要证据，没有扩展任务？

表格交付后再确认用户需要的文件格式。未指定时不自行假定 Excel 或 HTML；用户已指定则直接沿用。生成文件时使用适合该格式的工具或技能，保留来源和证据标签。未经授权不写入外部文档或发布。
