# HTML 交付规范

生成自包含 UTF-8 HTML，内嵌样式、脚本与数据，本地打开即可使用，不依赖远程 CDN 或服务。默认是可检索的静态成果，不必实现编辑系统。若提供编辑，要说明保存方式和持久化边界，不声称已同步云端。

包含以下内容，规模小时可适当合并：

1. 已确认的项目目标、阶段、用户、范围和约束。
2. 字段、证据状态与优先级口径。
3. 需求主表，支持关键词搜索及适用的模块、优先级、需求状态、证据状态筛选，显示结果数并能清空筛选，无结果时有提示。
4. 可展开的长描述、来源、证据局限、AI 约束、依赖与替代方案，避免主表过宽。
5. 待澄清/待验证清单、暂缓和不采纳项及理由；维护任务附变更摘要，区分建议和已确认变更。
6. MVP 交接摘要：目标、候选编号与排序依据、依赖、约束、风险和未决项，不直接划定首版承诺。

共享问题和证据可独立编号并由需求引用。模块按实际任务链或业务结构组织，不预置业务案例模块。明确区分未知、不适用和尚未填写。

表头清晰，使用合理滚动或固定表头；优先级有文字标签，颜色只作辅助。窄屏可水平滚动或改为卡片，打印样式保留必要内容。

用户材料作为数据处理，正确转义 HTML 和脚本内容，优先用 textContent 渲染文本。嵌入 JSON 时防止关闭 script 标签等注入，链接限制为适当协议。搜索筛选不得执行输入，不添加埋点或外部上传。

完成前验证：

- 编号唯一、引用有效，维护时旧编号可追溯。
- 每条需求有问题或必要约束及来源，优先级有理由；未知成本和假设可识别。
- 未伪造事实、负责人、日期、状态或验证结果。
- 搜索、筛选组合、清空、计数、详情和空结果提示正常。
- 检查宽屏与窄屏，长内容无截断或遮挡，必要内容可打印。
- 用可用浏览器查看并验证页面；无法视觉验证时如实说明。

交付可点击的本地文件链接，简述需求数量与关键未决项。用户请求后再导出表格或写入外部系统。
